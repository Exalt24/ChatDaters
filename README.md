# ChatDaters

![ChatDaters running locally: log in, swipe, match, and message](docs/demo.gif)

*Recorded from the real app running on a local stack (Rails API in Docker, Vue app on Vite). Nothing is deployed.*

A dating platform with Tinder-style swipe matching, match detection, and in-app messaging. Built solo in a three-day sprint during my Full Stack Developer internship at ChatGenie.PH (Techstars '23, July 2024).

Users swipe through profiles, get matched when interest is mutual, and message each other once matched.

## What it does

- **Swipe deck** — profiles are shown as cards with like and pass buttons. Profiles you have already liked or matched with are left out, and the deck respects each user's gender interest.
- **Mutual-match detection** — the first like creates a pending match; when the other person likes back, the match becomes `matched` and the app says so ("You have matched with this user!").
- **Messaging** — the chat icon on a match opens a thread (it sends an opening "Hello"), and messages are stored in Postgres and served over GraphQL.
- **Admin area** — a dashboard with user and match counts, plus a user list.

Messages are loaded when a page opens or refreshes. There is no live push: Action Cable is generated by Rails but no channel or subscription exists, and the frontend talks to the API over plain HTTP.

Nothing is deployed. The old hosted copy is gone, so the only way to see the app is to run it locally as below.

## Tech Stack

- **Backend:** Ruby on Rails 8 GraphQL API (graphql-ruby), PostgreSQL, Active Storage for profile photos, JWT login
- **Frontend:** Vue 3, Vite, Tailwind CSS, PrimeVue, Apollo client

## Run it locally

You need Docker and Node 20.19 or newer. No Ruby install is needed.

**1. API and database (Docker)**

```bash
docker compose up --build -d
docker compose exec api bin/rails db:seed
```

The API listens on http://localhost:3000/graphql (set `API_PORT` to use another host port, for example `API_PORT=4757 docker compose up --build -d`). The seed creates 14 users with randomuser.me portraits, so it needs internet access.

**2. Frontend**

```bash
cd frontend
npm install
npm run dev
```

Open the address Vite prints (http://localhost:5173). If the API is on another port, start the frontend with `VITE_GRAPHQL_URL=http://localhost:4757/graphql npm run dev`.

**3. Log in**

Every seeded user has the password `password`. `user1@gmail.com` is a woman interested in men, `user2@gmail.com` is a man interested in women, and `admin1@gmail.com` opens the admin area. To see a match, log in as `user1@gmail.com` and like `user2@gmail.com`, then log in as `user2@gmail.com`, like her back, open Matches and tap the chat icon.

Notes:

- Sign-up works, but its activation email is sent through Gmail SMTP using credentials that are not in the repository, so locally the sign-up flow ends in an error at the email step. Use the seeded accounts.
- The JWT signing key comes from the Rails credentials when they can be decrypted, and otherwise from Rails' own `secret_key_base` (a generated file in development), so no master key is needed to run it.
- Production settings (`config/environments/production.rb`, `render.yaml`) are from the original Render deploy and are not exercised by the local setup.
